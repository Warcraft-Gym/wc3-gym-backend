# One model

Every event kind shares the rows: `league`, `event`, `event_stage`, `event_round`, `event_division`, `event_entrant`. GNL and KOTH play on `matches` (fixtures), `series`, `series_side` and `series_game`; a cup plays on its own tables, see [cup series](#cup-series). A GNL season is the `gnl` kind of event; it runs on the same tables and its payloads did not change when the tables were renamed. `tests/test_event_season_parity.py` pins the GNL fields on `EventPublic`.

The rule that keeps this workable: **the shared engine never branches on kind.** A kind that needs different behaviour gets a kind module (`app/services/koth/`, and the GNL draft and fantasy services) and, where it needs its own columns, a side table. Never write `if kind == "gnl"` inside a shared service. See [the decision](../decisions/unified-event-model.md).

The event API is the canonical HTTP surface for every kind. `EventPublic` includes the GNL map pool, rounds, score configuration, fantasy configuration and unscored-series count. `user_signup` exists only on `SeasonPublic` and is always empty; `signup_race` and `played_as` are always null there. A user's `signup_seasons` entries are `SeasonSummaryPublic` and carry that signup's `signup_race` and `played_as` (see [response shapes](../api/response-shapes.md)); event signup routes carry the caller's signup state.

# Stages

`EventStage` names the format, the best-of, the map rules, the scheduling mode, the ranking rule and the advance count. Formats: `round_robin`, `gnl`, `single_elimination`, `double_elimination`, `placement`, `swiss`, `koth`, `ffa`. A `placement` bracket splits every group into its winners and its losers each round, so the last round decides every place; `placement_lives` ends a run after that many losses, and the players who stop share the places of their group. The stage series read names each series' group in `place_from` and `place_to`, and the table gives a shared place one position. See [the decision](../decisions/placement-bracket.md). A stage may split into groups that merge at the next stage; a division never merges.

The cup engine (`app/services/cup_engine.py`) draws the series of a cup's stage, follows results through the feeder graph, and ranks the entrants. Only a cup's stages are drawn: a `gnl` stage is drafted by its admin and its captains and a `koth` stage is paired by its admin during the night, so the engine refuses either. A Swiss stage draws one round at a time. An `ffa` stage plays lobbies whose result is an order of places. The stage engine (`app/services/stage_engine.py`) keeps what a KOTH night and a GNL season reach on `series`: a result moves the KOTH crown and fills a chain, and a stage read answers the night's series and its table. A `koth` stage is a chain per division.

A bracket stage may name the best-of of each part of its bracket in `best_of_by_round`, counted back from the end; the draw writes it onto each round, and a part it leaves out plays the stage's `best_of`. An event with `veto_by_best_of` vetoes each series by its own best-of, so its pool must hold the longest series; the create, a stage or pool write and the draw refuse a smaller pool. See [the decision](../decisions/cup-veto-by-best-of.md).

In a single elimination that plays a third-place series, that series decides places 3 and 4 and the final decides places 1 and 2; a beaten semi-finalist never ranks above the runner-up.

`app/services/series_rules.py` answers the rules a `series` row plays under: a KOTH series reads them from its round, its stage and its event; a GNL series reads them from its season. The shape of the row decides, never the kind. A cup series reads its rules from its round and its stage in `app/services/cup_reads.py`.

# Phase

An event's phase is derived on every read and never stored. The rungs, read from the last one back: `draft` while the event is unpublished; `finished` when an admin closed the event (`event.closed_at`), when the last stage by position holds series, every one of them is scored and the stage does not plan as a chain, or when its end date has passed, or, for an event with no end date and no series, when the day it starts has passed; `running` once a series has started; `signups_open`; `checkin` while the check-in window of the next dated round is open; `seeded` otherwise. A scored stage with an empty stage after it reads `running`, so a cup whose playoff is still to be drawn is not finished. A chain grows while its admin names series, so a scored chain reads `running` until the close stamps the event. An event whose teams are drafted (`entrant_kind` is `drafted_teams`) is finished by the close alone: its series are drafted round by round, so neither the last result it holds nor its end date ends it. A list read answers the phase of a page of events from one grouped count, never one query per event.

# The list reads

`GET /events` and the events of `GET /leagues/{league_id}` read newest start first: by the start time, else the start date, with an event that has neither last and the newer id first on a tie. The order and the page are cut in SQL. Both reads take `archived`: `false` leaves out every event that has a [koth_history_event](../data/tables/koth_history_event.md) row, `true` keeps only those, and no value keeps both. Each listed event carries `archived`: `true` when it has that row, else `false`, read as a column of the page statement. `POST /events/search` carries it the same way. `X-Total-Count` on `GET /events` counts the filtered set.

# The member read

`GET /me/events` answers one row per published event that is not an archived KOTH night, with the caller's own state on it: the entrant, the race of every live entrant row of the caller in `entrant_races` (an event that takes one entry per race holds one row per race, and a caller who is not entered reads an empty list), the check-in shape and its window, the next dated round, the phase and the one action the page offers. A caller who holds a captain seat in the event also gets `captain_fixture`: the own team's fixture of the next round that still has places left, with the two teams, the round's dates, `series_per_round` and the counts of published series, played series and open drafts, so the home page links the round draft before the fixture holds any series. While the event is not closed, the same caller gets `captain_matches`: every fixture of that team in the event, in round order and in the same shape, so the home page leads to the team's match of any round, drafted or not, running or over. Every other caller reads null and an empty list. The whole list costs a fixed number of statements whatever it holds, six of them for the captain fixtures; it loads only the event columns a row uses and only the rounds that are not over or have no dates.

# Entrants, seeds, divisions

An entrant is a player or a pre-made team in one event, with a race, a seed, a division, and eligibility warnings (`min_games`, `mmr_min`, `mmr_max`, a ban). Warnings show on the row and never refuse a signup, except on an event with `eligibility_required` on: there a player signs up, or is added by hand, only with a battle tag that W3Champions rates on the signup race, inside the MMR bounds and the games floor, and the refusal names the rule it missed. An event that also turns on `bnet_required` asks for that battle tag to be verified through Battle.net, and takes members only, because a battle tag alone proves no Battle.net link. An event that names `race_games_min`, which every cup does with 20, rates the player on the races they have really played: a race counts once its lifetime games on W3Champions reach that number, the best current rating among those races is checked against the bounds, the games floor counts the window over every race, and a player with no race over the limit is refused; the race of the signup then decides nothing. The lifetime games read every stored season, and a signup to such an event reads a player's past seasons once and keeps them (`users.w3c_history_through`). A GNL season and a KOTH night never turn it on. Without `race_games_min` the games rule is one rule: `min_games` ladder games on the signup race, counted over the live W3C window, the current season and the one before it, or over the current season alone where `min_games_seasons` is 1. Seeds come from MMR, a shuffle, a hand order, the previous stage, a qualifier or an invitation. Seeding from a qualifier is not built: an event names the event it feeds through `parent_id`, and the seed write answers `not_built` until the parent reads its qualifiers' tables. The draw seeds the unseeded entrants of the first stage by the stage's `seed_source` and locks the seeds; a locked stage refuses a reseed until it is unlocked. An event with `hide_seeds` on answers seed numbers only to its runners. A seed from the previous stage and the advance to the next stage read one order, and both refuse with a 400 while any series of that stage has no result.

Divisions cut the entrant pool by MMR (`app/core/divisions.py`). A band list that names a lower bound for every band takes no entrant without a rating: that entrant stays unplaced until an admin places it. Every division runs the same stage list on its own; a merged playoff across divisions is never a rule in the app.

A cup chooses at creation whether it splits its players ([cup_settings](../data/tables/cup_settings.md) `uses_divisions`), and these rules hold on a cup alone (`app/services/cup_divisions.py`); every other kind keeps the rules above:

- A cup without divisions refuses every division write and plays one field.
- A cup with divisions refuses its draw while a playing entrant stands in no division ("Place every player in a division first"), and refuses a new division list or cut once it is drawn, until the draw is undone.
- A cup pins a player's division and its seed apart ([cup_entrant_pin](../data/tables/cup_entrant_pin.md)): a new cut keeps the seed pins, and a reshuffle keeps the division pins.
- `PUT /events/{id}/stages/{stage_id}/seeds` may name a `division_id`, and then seeds that division alone and leaves every other one as it was; without it the write is as before for every kind.
- With `hide_seeds` on, the entrant read also leaves `seed_source` and `mmr_at_seed` null for a caller who does not run the cup.
- A cup's seeds change after the draw: `PUT /events/{id}/stages/{stage_id}/seeds/redraw` takes the body of a seed write, takes the stage's draw back, writes the seeds and draws the stage again in one transaction, so the bracket follows its seeds at once; a stage not drawn yet is drawn by the same write. A stage whose series hold results answers 409 until the call sends `confirm=true`, which deletes them, a refused draw keeps the draw that stood, a stage that pairs by round draws its first round again, and a later stage, which plays what the stage before sends on, is refused. A `division_id` on a drawn stage takes back and draws that division alone, and every other division keeps its series and results: a bracket draws it again aligned on the rounds the stage holds, so it still ends on the shared final, and a stage that pairs by round draws its first round for it again, its later rounds following as its results come in. The confirm then counts that division's results alone.

# Signup policy

`signup_policy` is `members` (a member with an account) or `anyone` (any battle tag; KOTH takes signups from Twitch chat this way). A per-event switch allows one entrant row per race, off by default, on for KOTH nights.

An event of a league that drafts its teams (`entrant_kind` is `drafted_teams`) takes no direct signup, and the write refuses it by that shape, never by the event kind. A captain of a team may enter that team into an event of the same league. A cross-league team is refused. The entrant cap refuses a signup past it and no waiting list is kept.

# The home hub read

`GET /home/series` is the one read behind the home page's series panels, and it
crosses every kind: a GNL fixture, a cup bracket and a KOTH night answer side by
side. It needs no token. It holds three lists, `next` (the five soonest booked
series), `casts_upcoming` (three of those a caster has claimed)
and `casts_recent` (the four newest played series whose cast carries a VOD). A
booked series is one with no result whose start is no more than two hours past,
so a series that is being played right now still has a card and leads the list. A
draft pairing and an event that is not published never appear. Each row carries
what a card prints and nothing more: the label in parts (`league`, `event`,
`stage`, `round`), the two fixture teams, each side as id, name, country, the
race the row names and one rating, the two map scores, and one cast with its
link. An empty field is left out of the row, so a reader defaults a missing key
to null. The answer is cacheable at the edge for two minutes. Its worst case is
twelve fixture rows that each carry two team icon URLs; that body is about seven
and a half kilobytes raw and under four kilobytes compressed, which is what the
edge sends. It costs a fixed number of statements, none of them per row.

`GET /home/series/upcoming` is the page behind the hub's "All upcoming": every booked series of a published event in time order, at most 100, by the same rule as `next`. Each row is the hub row with every claim on it in `casts` in place of the one cast, so a caster claims, edits or leaves a cast from the list. It needs no token, is cacheable at the edge for two minutes, and costs the statements of one hub list, none of them per row.

# Cup series

A cup's series live in [cup_series](../data/tables/cup_series.md), with their games in [cup_series_game](../data/tables/cup_series_game.md), their veto in [cup_veto_step](../data/tables/cup_veto_step.md) and the seats of a lobby in [cup_series_side](../data/tables/cup_series_side.md). No GNL rule reads them and no cup rule reads a `series` row. See [the decision](../decisions/cups-own-tables.md).

One rule answers every write on a cup series: the player a side names, or a member of the cup team a side fields, acts for that side, and a runner of the cup (an admin, or one of its organizers) acts for either side. The routes:

- `GET /cup-series/{id}` reads one series as its box does, and `GET /cup-series/{id}/games` its games with the map the veto offers each.
- `PUT /cup-series/{id}/report` reports a result for a side: both scores, which finish the series at the wins its best-of takes, the games, checked against the score, and the races played. An off race that names the race the side entered on is dropped. The answer carries `veto_complete` and the games.
- `PUT /cup-series/{id}` is a runner's write or clear of a result; `force=true` allows a clear or a turned result that loses a later result below it.
- `DELETE /cup-series/{id}/result` takes a result back: a side takes back its own played result, and a walkover, a forfeit and `force` are a runner's.
- `PUT /cup-series/{id}/result-kind` is a runner's walkover or forfeit; `PUT /cup-series/{id}/places` and `/sides` are a runner's places and seats of a lobby.
- `GET` and `PUT /cup-series/{id}/veto` serve the board to a player of either side and to a runner. A player takes the steps of their own side and takes back what they entered; a runner records any step and takes back the last one.

A cup series posts no Discord card, takes no replay and no cast, and shows in no player history, head-to-head or Home list. The `/series` and `/player-series` routes answer `series` rows alone.

# Cup rounds

A cup is played on one evening, or over several rounds, each a competition of its own on its own date (`app/services/cup_rounds.py`). `POST /events` for a cup with `legs`, two or more, writes one [cup_leg](../data/tables/cup_leg.md) per entry and copies the body's `stages` into every round ([cup_leg_stage](../data/tables/cup_leg_stage.md)), so every round plays the same format. Players sign up once and check in per round ([cup_leg_checkin](../data/tables/cup_leg_checkin.md)); the cup-wide check-in is off. The full event read answers the rounds as `cup_legs`.

- A round draws and seeds the entrants checked in for it, and its stages seed from, and advance into, stages of the same round alone. A check-in is refused once the round is drawn, and a finished round keeps its draw until it is reopened.
- A signup after the first round is drawn joins the later rounds and goes on no waitlist; the entrant cap still holds.
- While the cup is open, `PUT /events/{id}/legs/{leg_id}` renames a round or moves its start, a start staying after the round before and before the round after; `POST /events/{id}/legs` adds a round after the last, playing the same stages; and `DELETE /events/{id}/legs/{leg_id}` removes a round that is not drawn, with its stages and check-ins, the later rounds moving up a number and a cup keeping two rounds or more. The first round's start is the cup's start, both ways: moving one moves the other.
- `PUT /events/{id}/stages` takes one round's stages and writes them onto every round; a body that changes how many stages a round plays is refused.
- A runner finishes a round once every series of it holds a result (`POST /events/{id}/legs/{leg_id}/finish`). Its places, read by `awards.event_places` over the round's stages alone, pay points from `cup_settings.points_by_place`, and every entrant's seed is cleared, so the next round seeds afresh. `DELETE` on the same path takes the finish back while the cup is open.
- `GET /events/{id}/overall` answers the overall table: each entrant's points from every finished round, a missed round paying 0, the points per round, and the best single place. Points rank first, then the best single place, then more of that place; entrants still level share their position. It is edge cached as the event is, and reads a fixed number of statements, each round's places one more.
- Closing a cup with rounds pays its awards from the overall table, one per entrant who played a finished round, the position its place.

# Recurring cups

A cup can repeat on a rule (`app/services/cup_recurrence.py`): a weekday, every week or the nth of the month (1 to 4, or the last), at a local start time in a time zone, with an optional last day ([cup_recurrence](../data/tables/cup_recurrence.md)). Each occurrence is a cup of its own with its own players, draw and awards ([cup_occurrence](../data/tables/cup_occurrence.md)).

- A runner of a cup that has a start sets the rule up with `POST /events/{id}/recurrence`; the cup becomes the first occurrence. `POST /events` for a cup may carry the rule as `recurrence`, which sets it up in the same transaction, so a refused rule creates no cup.
- `GET /cup-recurrences/{id}` answers the rule, its cups in day order and its next eight days from today, each with the cup made on it.
- A runner of the latest cup makes the cup of a coming day with `POST /cup-recurrences/{id}/occurrences`: a copy of the latest cup named after the rule and the day, its start on that day at the rule's time, its rounds moved by the same days, and the latest cup's organizers with the caller. No job makes a cup by itself.
- Stopping the rule (`DELETE /cup-recurrences/{id}`) keeps every cup it made.

# Awards

Closing an event freezes its places into `event_award`, one row per placed entrant per division: the last stage's table first, then each entrant no later stage played, after those, in the order of the stage before (`awards.event_places`), so a Swiss cup's players outside its playoff take places too. A trophy read lists a cup win or a KOTH crown from those rows without replaying the stage.

# Discord card

Every event has one card the app posts and edits in Discord, with two buttons, Sign up and Check in. A press writes through the same entrant service the site uses. The check-in button is enabled only while the event's check-in window is open, which the full event read answers as `checkin_open`; a press outside the window answers that the check-in is not open yet, or that it has closed. See [Discord integration](discord-integration.md).

# Team cups

A cup with `team_size` 2 to 4 plays real team games. A member signs a team up with `POST /events/{id}/cup-teams` and the names of the other players: the caller captains it, the team is a [cup_team](../data/tables/cup_team.md) of the cup with the caller its first [member](../data/tables/cup_team_member.md), and every other player gets a [cup_team_invite](../data/tables/cup_team_invite.md), which they accept or decline; the captain invites again or takes an invite back, a player who is not the captain leaves, and the captain withdraws the team. A withdrawn team takes its open invites with it, and one a runner removes with `DELETE /events/{id}/entrants/{entrant_id}` takes its players too, so every player of it is free for another team. A cup enters the teams made for it and refuses a league team. An event's runner enters a whole team with `POST /events/{id}/cup-teams/admin` and swaps a player with `POST /events/{id}/cup-teams/{team_id}/members/{user_id}/replace` until the team has played. Every player is held to the cup's eligibility on their own, a player stands in one team of a cup at most, and the draw refuses while a team is short of players. `GET /events/{id}/entrants` answers each cup team's roster, the captain first and each player with the rating the cup checks, and its open invites; `GET /me/team-invites` answers the caller's. Any player of the roster checks the team in, vetoes and reports. `GET /maps/ladder-import?mode=2v2` or `4v4` reads that ladder pool. See [the decision](../decisions/cup-teams-live-for-one-cup.md).

# Managing an event

The path from a new league to a finished event, in order. Every write here needs a runner of the event, an admin or one of its [organizers](roles-and-permissions.md#organizers), unless the step says otherwise; creating a league and posting the Discord card stay an admin's. The frontend repository owns the pages.

1. **Create the league.** `POST /leagues` with the name, the short name, the `kind` and the `entrant_kind`. `PUT /leagues/{id}` changes it later. The GNL and the KOTH league already exist.
2. **Create the event.** `POST /events` with the league id, fields and optional stage list. A GNL league dispatches to its kind service, which writes one `gnl` stage, the requested rounds, the ordered map pool and the achievement rules in the same transaction. The caller does not also send `kind=gnl`; the league selects those rules and the default already has that value. A generic event body without `stages` gets one default stage; an explicit empty list gets none, which is a signup-only event. `entrant_kind` left out is copied from the league. `PUT /events/{id}` changes the fields; an event that already holds teams must remove them before its league can change. `PUT /events/{id}/stages` replaces the stage list in play order, updating a stage in place so its rounds and series stay, and refusing to drop a stage that still holds rounds. A KOTH night is opened in one call, `POST /koth/nights`, which writes the event, its `koth` stage and its three brackets.
3. **Publish.** `PUT /events/{id}` with `published` on. A draft reads for an admin only and its phase is `draft`.
4. **Open signups.** `PUT /events/{id}` with `signups_open` on; the phase reads `signups_open`. A finished event answers `signups_open` false on every read and refuses a signup. `POST /events/{id}/discord-post` posts the event card with its buttons in a channel, or edits the card already there.
5. **Entrants.** A member signs up with `POST /events/{id}/entrants`, a captain enters their team the same way, an admin enters anyone with `POST /events/{id}/entrants/admin` whether signups stand open or not, and a Twitch chat command enters a battle tag through `GET /koth/signup`. A cup whose first stage is drawn, or that holds `entrant_cap` entrants, puts a member's signup or a captain's team on its waitlist (`waitlisted_at`) instead of refusing it, eligibility still held, and the caller's action reads `waitlisted`. A waiting entrant takes no seat in the cap, the draw, the seeds, check-in or the counts. A runner lets one in before the draw with `POST /events/{id}/entrants/{entrant_id}/admit`, past the cap if need be; after the draw a waiting player comes in through the replace write, in the place of one who has not played. Undoing a draw leaves the waitlist as it is. `DELETE /events/{id}/entrants/me` withdraws and keeps the row, every row of the caller or the one race a `race` query parameter names, and a runner withdraws one entrant with `POST /events/{id}/entrants/{entrant_id}/withdraw`. On a drawn cup a withdrawn entrant, a team included, forfeits every series it still owes: an open series at once, and a series it reaches later as soon as both its sides fill, so its opponents go through; a series both sides left is a forfeit nobody wins. A withdrawn entrant takes no place in the table. A KOTH night settles its leavers on its own, and a GNL season forfeits nothing; `DELETE /events/{id}/entrants/{entrant_id}` removes it, except on a KOTH night, which removes a player on its run page. `POST /events/{id}/entrants/{entrant_id}/checkin` checks an entrant in on an event with no dated round; an event with dated rounds checks in per round through `PUT /player-availability`. `GET /events/{id}/entrants` lists every row with its MMR and its warnings. A signup that names a battle tag refuses one that is not shaped `Name#1234`, because the tag is the identity of a player with no account. `entrant_count` on the event and on each division counts players, so two races of one player count once.
6. **Divisions.** `PUT /events/{id}/divisions` replaces the list, strongest first, clears every placement and clears the division off every series and match that named one. `POST /events/{id}/divisions/assign` cuts the live entrants by the MMR of their signup race, leaving hand-placed ones alone; a hand-placed entrant takes one of its division's seats, so a sized division never holds more than its size. `PUT /events/{id}/entrants/{entrant_id}` moves one entrant by hand and gives it the last place in the line of its new division; a division whose king it was loses that king, because a division's king is a row of that division. A KOTH night refuses the division write and the cut, and refuses a move by hand once it is closed; see [KOTH night](koth.md).
7. **Seeds and the lock.** `PUT /events/{id}/stages/{stage_id}/seeds` numbers the entrants 1..n inside each division from a `source`: `mmr`, `random`, `manual` with an `order`, `invitation`, or `previous_stage`, which reads the standings of the stage before and refuses while a series of it has no result. An entrant with `manual_placement` on keeps its seed and the others take the free numbers of their division, except from `previous_stage`, whose standings decide alone. Each stage names a `seed_source`, `mmr` (the default), `random` or `manual`, which the draw applies to the entrants that have no seed yet; a stage write that leaves it out writes `mmr`. `POST /events/{id}/stages/{stage_id}/seeds/lock` stamps the stage, and the draw stamps it too. A locked stage answers a seed write with 409, and a move to another division by `PUT /events/{id}/entrants/{entrant_id}` answers 409 while any stage of the event is locked. `DELETE /events/{id}/stages/{stage_id}/seeds/lock` unlocks the stage and answers it; it answers 409 while the stage holds series, so a drawn stage is taken back first. A KOTH night refuses a seed write, because its line is ordered on its run page.
8. **Generate.** `POST /events/{id}/stages/{stage_id}/generate` writes every series of the stage from the seeds, one bracket per division, locks the seeds, and refuses a `gnl` stage, a `koth` stage and a stage that already holds series. On the first stage it first seeds every live entrant that has no seed by the stage's `seed_source`, after the last seed of its division: `mmr` by the newest rating, highest first and the unrated last, `random` by a shuffle, and `manual` answers 409 until every entrant has a seed. The seeds and the draw are one transaction, so a refused draw writes no seed. A later stage plays the seeds `advance` wrote and fills none. The first `POST /events/{id}/stages/{stage_id}/rounds` of a stage seeds and locks the same way. A double elimination bracket drops the losers of each upper round into the lower bracket reversed, and every second drop round also shifts its halves, so two players who just met do not meet again at once. A stage that draws by round (`swiss`, `koth`) takes `POST /events/{id}/stages/{stage_id}/rounds` once per round. A Swiss stage plays the rounds `swiss_rounds` names, cut to the rounds its field holds without a pairing twice. A stage played straight away (`scheduling_mode` `immediate`, as a cup is) plays on by itself: the last result of a Swiss round draws the next round, a result of a round stays fixed once the next round is drawn from it, and a stage with `auto_advance` that ends seeds the next stage and draws it in the same write, a cup's top-cut playoff. `POST /events/{id}/stages/{stage_id}/series` appends a challenger to a chain. A round robin over a cup's teams writes one series per pair, each team a side. A GNL season is not generated: its fixtures come from the match routes and its series from the captains' drafts.
   `DELETE /events/{id}/stages/{stage_id}/series` takes a draw back until the event is finished: the stage's rounds go, and with them every series, result, veto, replay and cast, and the seeds open again, so the field may change and be drawn anew; a stage whose series hold results answers 409 with how many until the call sends `confirm=true`. It answers how many series and played results went, refuses a GNL or KOTH stage and waits for a later drawn stage to go first. `POST /events/{id}/entrants/{entrant_id}/replace` puts another player in the place of one who has played no match yet: the new row takes the seed, the division and every series of the old one, a veto begun in a series still open starts over, the new player is held to the event's rules as a hand-added player is, and the old row leaves.
9. **Results.** A cup's series take their results on the [cup series routes](#cup-series). On a GNL or KOTH series the player a side names, a captain of its team, or an admin reports through `PUT /player-series/{id}`, and an admin records a walkover or a forfeit with `PUT /series/{id}/result-kind`. A score follows the feeder graph into the next series by itself. `GET /events/{id}/stages/{stage_id}/series` and `GET /events/{id}/stages/{stage_id}/standings` read the run and the table; both are open reads. A stage series row names where each fed side comes from in `slot1_source` and `slot2_source`, such as `Loser of UB R1 M3`: the outcome, the feeder's round with `UB` and `LB` for the two halves and `R` for round, and the feeder's place in its round; a seeded side reads null, and only this read fills them. Each row also carries `entrant1_seed` and `entrant2_seed`, which read null when the event has `hide_seeds` on and the caller does not run it; `GET /events/{id}/entrants` answers that caller every `seed` null and lists the entrants in signup order. Only the anonymous answer of either read is edge cached. A stage series row carries a reduced player, which holds no W3Champions stats, so the row names the rating of each side on the race it plays in `player1_mmr` and `player2_mmr`: the `w3cstats` rating on a running event, the MMR of the time (`mmr_at`, see [Ladder and achievements](ladder-and-achievements.md)) on a finished one. Three reads tell the two apart; the running rows are rated in two statements, three while the W3Champions season setting is unset, and a finished event in one statement. A side with no rating on that race reads null.
10. **Advance.** `POST /events/{id}/stages/{stage_id}/advance` seeds the next stage from the top places of every division's table and refuses on the last stage or while a series has no result. A stage with `auto_advance` does this on its last score.
11. **Minimum and cancel.** `entrant_min` names the fewest entrants the event is played with: the draw of its first stage refuses while fewer would play, counting every entrant that has not withdrawn, so a runner withdraws the no-shows first. A runner who calls the event off sends `POST /events/{id}/cancel`, which stamps `closed_at` and `cancelled_at` and pays no place; the event reads finished, takes no signup and refuses a finish until `POST /events/{id}/reopen` clears both stamps.
12. **Finish and awards.** `POST /events/{id}/finish` closes the event: it stamps `closed_at`, whatever results are still missing, and writes the `event_award` rows from the table of the last stage, one per placed entrant per division. A second call keeps the stamp and rewrites the rows. `POST /events/{id}/reopen` takes the close back: it clears the stamp, deletes the event's award rows and answers the event, which reads by its series again; an archived night refuses it. A KOTH night closes with `POST /koth/nights/{id}/close`, which deletes the series nobody played and then pays the awards. [Phase](#phase) lists when the event reads `finished`.
